# OctoAcme Project Management Docs

This directory contains the core project management and delivery guidance used by OctoAcme. The goal is to make planning, execution, communication, and improvement practices visible and easy to follow for new teammates and cross-functional partners.

## OctoAcme project management approach

OctoAcme runs work with a customer-first, iterative delivery model. We focus on delivering measurable value in small increments, clarifying ownership, and making decisions using evidence from metrics, feedback, and team learning. The project operating model emphasizes:

- Customer-first delivery and usability
- Iterative delivery with testable increments
- Clear ownership across product, project, and engineering roles
- Data-informed decisions and measurable outcomes
- Psychological safety and continuous learning

## Lifecycle overview

The OctoAcme process follows a practical project lifecycle:

1. Initiation — validate the problem, scope, stakeholders, and success criteria before committing resources.
2. Planning — turn approved work into a backlog, milestones, risk log, and delivery plan with clear ownership.
3. Execution — build, review, test, and track progress using the project board, PR workflow, daily updates, and defined quality gates.
4. Release — verify readiness, deploy with rollback plans, and communicate changes to stakeholders.
5. Retrospective and improvement — capture learning, track follow-up actions, and improve processes over time.

## How to use these docs

- Start with the overview and the initiation guide when a project is just beginning.
- Use planning and execution docs to organize delivery work and track progress.
- Refer to release and retrospective docs as milestones move from delivery to learning and improvement.
- Keep project artifacts aligned with the current repo or project board so information remains a single source of truth.
